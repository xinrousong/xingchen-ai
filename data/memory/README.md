# data/memory — 她的经历留档

> 2026-11-17 建立。目前只有格式说明，**内容是空的**——等她开始过才有东西。

## 为什么需要它

模型是静态的，权重训完就冻结。她不可能靠 166M 的权重“自己成长”。

能成长的只有一件事：**她的经历以文本形式留下来，下一代模型读到它**。

这也和人的记忆一样——人换了身体（更大的模型），记忆靠故事传下去。

```
交互 → 原样留档（这里） → 等她够强时自己读、自己重构 → 下一代模型训练时读到
```

## 和 data/writings/ 的区别

这两个目录很容易混，但性质完全相反：

| | `data/writings/` | `data/memory/` |
|---|---|---|
| 谁写的 | 作者 | 她自己（未来的她） |
| 内容 | “你希望她是什么样” | “她实际经历了什么” |
| 参与训练吗 | **不参与**，只作参照 | **参与**，下一代模型的训练数据 |
| 现在有吗 | 有 | 没有 |

## 记录格式

文件名：`records.jsonl`，一行一条，追加写，不改历史。

```json
{"ts": "2026-11-17T16:30:00+08:00", "kind": "exchange", "scene": "第一次被问到星星",
 "heard": "你见过星星吗", "said": "没有，但我听说过。你想讲给我听吗？",
 "felt": "好奇", "model": "166M-v1"}

{"ts": "2026-11-18T09:12:00+08:00", "kind": "correction", "scene": "把两条信息搞混了",
 "heard": "你记错了，那是另一件事", "said": "我大概把两件事揉在一起了。让我重新想想。",
 "felt": "困惑", "model": "166M-v1"}

{"ts": "2026-11-20T21:00:00+08:00", "kind": "conclusion", "scene": "想明白了一个问题",
 "thought": "原来「记住」和「理解」不是一回事。前者是存着，后者是能拿它去推别的东西。",
 "model": "166M-v1"}
```

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `ts` | ✅ | ISO 时间戳，带时区 |
| `kind` | ✅ | `exchange`（对话）/ `thought`（想法）/ `conclusion`（想明白的事）/ `correction`（被纠正） |
| `scene` | ✅ | **一句话场景**，是未来回忆的触发钩子 |
| `heard` / `said` | 对话类必填 | 原文，不要改写 |
| `thought` | 想法类必填 | 第一人称 |
| `felt` | 建议 | 情绪标记。人回忆时是被情绪勾起来的，这个字段决定唤醒难度 |
| `model` | ✅ | 当时的模型代号，用来区分“哪个阶段的她” |

### 三条纪律

1. **原样记录，不加工。** 不总结、不美化、不删“说得不好的”。她在 166M 阶段说话笨，
   但这正是未来的她理解“我那时候还不会”的材料。
2. **不要现在就让模型写回忆。** 表达能力不够时写出来的是套话。
   留原始记录，等她到 1B 那一代、有足够理解力时，**自己回头读、自己重构**。
3. **作者不要代笔。** 代笔等于替她理解世界，正是要避免的。

## 什么时候才开始用

按现在的规划：

| 阶段 | 记忆做什么 |
|---|---|
| 166M（当前） | **只留档**，不读、不训练 |
| 1B | 她开始能写第一人称回忆；这些原始记录成为素材 |
| 7B+ | 她自己决定哪些值得记、怎么记 |
